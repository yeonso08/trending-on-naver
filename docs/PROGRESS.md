## 1. 지금까지 한 일

### 1-1. 폰트 정리

`next/font`의 Inter를 쓰면서 `globals.css`가 `body`에 Arial을 다시 지정해 서로 충돌하고
있었습니다. 한글 폰트는 지정된 적이 없었습니다.

**Pretendard Variable**(SIL OFL 1.1, 상업적 이용 가능)로 교체하고 자체 호스팅합니다.
전체 variable 파일은 2MB라 통짜로 쓰지 않고 **동적 서브셋 92개**를 넣었습니다.
브라우저가 `unicode-range`를 보고 필요한 조각만 받습니다.

- 메인 페이지 기준 실제 다운로드: **8개 / 약 206KB** (통짜 대비 10배 절감)
- 사용 빈도 상위 3개(라틴 + 최빈 한글)는 preload
- 외부 CDN을 쓰지 않아 추가 DNS/TLS 왕복이 없습니다

### 1-2. 디자인 전면 개편

shadcn 기본값 그대로였던 초록 primary와 radius 1rem 조합이 전체를 템플릿처럼 보이게
만들고 있었습니다. 디자인 토큰부터 다시 잡았습니다.

- 주요 액션은 near-black — 채도 대신 대비로 위계를 만듭니다
- 강조색은 오렌지 하나로 제한하고 순위 1~3위, 실시간 표시, 호버에만 사용
- radius 1rem → 0.75rem, 그림자 대신 얇은 보더
- 순위 숫자에 `tabular-nums` — 자릿수가 바뀌어도 열이 흔들리지 않습니다
- 헤더/푸터 셸 추가, 라이트/다크/모바일 모두 확인

### 1-3. 콘텐츠 확장과 SEO

구글 트렌드 RSS는 제목·시각 외에 **검색량, 썸네일, 관련 뉴스**까지 주는데 기존 코드는
전부 버리고 있었습니다. 이를 살려 검색어 상세 페이지를 만들었습니다.

- `/keyword/[keyword]` — 관련 뉴스 + 최근 30일 검색 관심도 (SSG)
- `/analysis` — 대시보드를 분리. 메인 First Load JS **304kB → 115kB**
- `/about`, `/privacy`, `/terms` — AdSense 심사에 필요한 정적 문서
- `sitemap.xml`(순위권 검색어 포함), `robots.txt`
- 페이지별 메타데이터 + canonical, OG/Twitter 카드

### 1-4. 광고 지면 확보

`AdSlot` 컴포넌트로 리더보드·사이드바·인피드 3종을 배치했습니다.
지면 크기를 미리 잡아 두었으므로 실제 광고가 들어와도 레이아웃이 밀리지 않습니다(CLS 방어).

**아직 자리표시자입니다.** `debug` prop이 켜져 있어 점선 박스가 보입니다.

### 1-5. 데이터 출처 정리 (영리 목적 전제)

광고 수익이 목표이므로 이용 조건을 확인했습니다. 자세한 내용은 `CLAUDE.md`의
"데이터 소스와 라이선스" 절에 있습니다. 요약하면:

| 항목 | 결론 |
|---|---|
| 구글 트렌드 RSS | **공식 제공 형식.** 실시간 인기 페이지 `내보내기` 메뉴가 이 URL로 연결됩니다. 출처 표기 의무만 지키면 됩니다 |
| 구글 임베드 위젯 | **실시간 인기에는 없습니다.** `탐색(Explore)` 차트에만 제공됩니다 |
| 네이버 실시간 검색어 | **2021년 2월 폐지.** 대체 불가 |
| 네이버 데이터랩 | 키워드를 직접 넣어야 추이를 주는 API. 실시간 순위를 대체할 수 없습니다 |

작업 중 브라우저 User-Agent 위장 헤더를 제거했습니다. 없어도 정상 응답하므로 애초에
불필요했고, 영리 서비스에 남길 이유가 없는 코드였습니다.

### 1-6. 네이버 API HUB 이관

2026년 6월 검색어 트렌드 API가 NAVER API HUB(네이버클라우드)로 이관됐습니다.
구 개발자센터 방식은 2027년 6월 30일까지만 동작합니다.

요청·응답 바디가 두 방식에서 완전히 같으므로, `shared/api/naver-datalab.ts`가 엔드포인트와
인증 헤더만 갈아끼우는 식으로 **양쪽을 모두 지원**합니다. 이관이 끝나면 구 방식 분기를
지우면 됩니다.

### 1-7. 쿼터 소진 구조 수정

`KeywordTrendChart`가 `useEffect`로 `/api/trends`를 부르고 있었습니다. 페이지 HTML은
ISR로 캐싱돼도 그 호출만은 매번 브라우저에서 나가기 때문에 **페이지뷰 1회 = 네이버 API
1회**였습니다. 유입이 늘수록 서비스가 망가지는 구조입니다.

서버로 옮기고 `unstable_cache`(TTL 6시간)를 씌웠습니다. 네이버 데이터랩은 POST라
Next.js의 fetch 캐시 대상이 아니어서 `unstable_cache`가 필요합니다.

> 계측 결과: 서로 다른 키워드 3개 × 각 2회 요청(6 페이지뷰) → 실제 호출 **3회**, 재요청 0회.
> 검색어 하나당 하루 최대 4회로 묶입니다.

### 1-8. 함께 고친 버그

- **`generateStaticParams` 이중 인코딩** — 이미 `encodeURIComponent`된 slug를 넘겨
  Next.js가 한 번 더 인코딩했습니다. **한글 검색어 페이지 10개 중 9개가 not-found로
  프리렌더**되고 있었고, 라틴 문자 검색어(`mlb`)만 멀쩡해 발견이 어려웠습니다.
- **`Loading.tsx` → `loading.tsx`** — Next.js는 소문자만 인식합니다. macOS는 대소문자를
  구분하지 않아 로컬에선 동작하는 것처럼 보였지만 Vercel(Linux)에선 적용되지 않았습니다.
- **`DeviceType`의 `'m'` → `'mo'`** — 네이버 실제 스펙은 `pc`/`mo`이고 폼은 이미 `mo`를
  보내고 있어서, 모바일 선택 시 검색 조건 표시가 `undefined`였습니다.
- **검색 폼 기본값** — 날짜가 비어 있고 연령대가 하나도 선택되지 않아 처음 열면 검증
  실패부터 보게 됐습니다. 최근 30일 + 전체 연령대로 시작합니다.
- **구글 RSS 실패가 빌드를 깨뜨리던 문제** — 조회 실패 시 예외를 던져 프리렌더 단계가
  통째로 실패했습니다. 빈 배열 반환 + 10초 타임아웃으로 바꿨습니다.
- 죽은 코드 제거: `use-trend-data.ts`(POST 라우트에 GET 호출), `trending-detail.tsx`,
  `shared/api/base.ts`와 `axios` 의존성, 잔존 `console.log`

### 1-9. 보안 업데이트

`next` 15.1.3은 2024년 12월 버전이었고 `pnpm audit` 기준 취약점 **38건**(critical 2건)이
걸려 있었습니다. Vercel이 취약한 Next.js 버전의 배포를 차단하면서 드러났습니다.

- `next` 15.1.3 → **15.5.23** (15.x 보안 백포트 라인 최신)
- `postcss` → 8.5.26
- `fast-xml-parser` 4.x → 5.x (메이저. 실제 RSS 응답으로 v4/v5 파싱 결과가 동일한 것을
  확인하고 올림)

**38건 → 5건.** 남은 5건은 `next`가 고정한 내부 의존성(`postcss@8.4.31`, `sharp@0.34.5`)이라
직접 해소할 수 없습니다. 우리 직접 의존은 모두 패치 버전입니다.

## 3. 알고 있는 문제

곧바로 고칠 것은 아니지만 인지하고 있어야 하는 것들입니다.

**순위 밖 검색어가 soft 404입니다.** `notFound()`를 호출하지만 ISR 캐시를 거치면서 HTTP
상태가 200으로 나갑니다(Next.js의 알려진 동작). `generateMetadata`가 `noindex, nofollow`를
붙이므로 색인되지는 않습니다. `dynamicParams = false`로 바꾸면 진짜 404가 되지만, 그러면
빌드 이후 새로 뜬 검색어가 전부 404가 되므로 **쓰면 안 됩니다.** 근본 해결은 순위 3번입니다.

**네이버 무료 쿼터에는 조건이 있습니다.** 콘솔에 보이는 "당월 50,000회"는 기본 무료
30,000건과 한시적 무료 20,000건을 합친 값입니다. 뒤쪽 구간은 분류상 '유료'라 언젠가
과금될 수 있으므로, **안정적으로 기댈 수 있는 값은 30,000건으로 잡는 편이 안전합니다.**
문서상 429는 "하루 허용량 초과"로 설명되어 있어 일 한도도 있을 수 있습니다.

**`next`가 고정한 내부 의존성에 취약점 5건이 남아 있습니다.** `postcss@8.4.31`,
`sharp@0.34.5`. 우리 쪽에서 버전을 올릴 수 없고, `pnpm.overrides`로 강제하는 방법은 Next의
CSS 파이프라인에 영향을 줄 수 있어 택하지 않았습니다. Next를 올리면 함께 해소됩니다.

**Next.js 16이 나와 있습니다.** 지금은 15.5.23(15.x 백포트 라인)입니다. 배포 복구가
목적이라 메이저 업그레이드는 하지 않았습니다. 여유가 생기면 별도로 진행하세요.
